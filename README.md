# Java-тесты для Study Hub

Тренажёр для подготовки к техническому собеседованию по Java и Spring. Внутри банк контрольных
вопросов с эталонными ответами, тестирование на время и выгрузка результата, которую проверяет любой
ИИ-ассистент. Регистрации нет: приложение работает у вас локально в Docker, и вся история хранится в
вашей базе.

## Как устроено обучение

Слева дерево **курс → тема → урок**, у каждого узла число вопросов. Уроки соответствуют материалам
курса Study Hub: «Final», «String pool», «Garbage Collector» и т. д.

1. **Изучите вопросы.** Откройте курс, тему или урок. В основном окне будут все вопросы этого раздела
   и общее их число. Ответ под каждым вопросом раскрывается по клику «Ответ».
2. **Проверьте себя.** Когда материал прочитан, нажмите «Начать тестирование» в том же разделе.
3. **Разберите ошибки с ИИ.** Скачайте результат и прогоните его через ИИ-ассистента (см. ниже).
4. **Повторите слабые места** и пройдите тест ещё раз. Прогресс виден в «Моей истории тестирования».

Хорошая последовательность: урок → тема → весь курс. На уроке вопросов мало, их можно брать все. На
теме и курсе выбирайте 10–20 случайных вопросов и проходите тест несколько раз.

## Как проходит тестирование

- Перед стартом выберите число вопросов: 10, 20, 50 или все. Вопросы берутся случайно из выбранного
  раздела.
- Тест идёт мастером: один вопрос на экране, кнопки «Назад» и «Далее», на последнем вопросе
  «Сдать тест».
- **На каждый вопрос 2 минуты.** Таймер вопроса идёт, только пока вопрос открыт. Если уйти назад и
  вернуться, отсчёт продолжится с остатка. За 30 секунд до конца таймер краснеет.
- **Если время любого вопроса закончилось, тест сбрасывается** с результатом «Не сдан». Ответы такой
  попытки не сохраняются, но сама попытка попадает в историю.
- Отвечайте своими словами, как на собеседовании. Пустой ответ допустим, перед сдачей сайт спросит,
  точно ли сдавать с пропусками.
- **«Показать ответ»** открывает эталон и ничего не блокирует, но вопрос получает оранжевую плашку
  «Ответ просмотрен». ИИ-проверка не засчитает такой вопрос в «честный» балл.

## Как скачать результат

После «Сдать тест» результат сохраняется в историю, и появляются две кнопки. Каждая скачивает пару
файлов:

| Кнопка | Что внутри | Когда брать |
|---|---|---|
| Скачать результат (полный) | `JavaTestAgent_<дата>_<время>_full.md` и `JavaTestResult_<дата>_<время>_full.json` | Нужен подробный разбор: как надо было ответить, как это устроено внутри, примеры кода, вопросы интервьюера «вдогонку» |
| Скачать результат (упрощенный) | `JavaTestAgent_<дата>_<время>_short.md` и `JavaTestResult_<дата>_<время>_short.json` | Нужна быстрая проверка: балл, короткий правильный ответ и почему ваш ответ неверен |

Дата и время в имени — момент сдачи, например `JavaTestAgent_20.11.2026_14-05-33_full.md`. Так файлы
нескольких тестов за день не путаются и не перезаписывают друг друга.

- `.md` — инструкция (промпт) для ИИ-агента: как оценивать, как считать проценты, в каком виде
  писать отчёт.
- `.json` — ваш тест: вопросы, ваши ответы, был ли просмотрен эталон, эталонные ответы, время на
  каждый вопрос.

Браузер может спросить, разрешить ли сайту скачивать несколько файлов. Разрешите, иначе второй файл не
скачается.

## Как прогнать результат через ИИ

1. Откройте чат с любым ИИ-ассистентом: Claude, ChatGPT, Gemini и т. п.
2. Прикрепите **оба** файла из одной пары: `.md` и `.json`.
3. Напишите: «Выполни инструкцию из md-файла для приложенного json».
4. ИИ посчитает итоговый и «честный» балл, проценты верных, частичных и неверных ответов, покажет
   ошибки и, в полном режиме, подробно разберёт каждый вопрос.

Если отчёт длинный и ассистент остановился на середине, напишите «продолжай».

## Моя история тестирования

Ссылка в шапке сайта. В таблице все сданные тесты: дата, что тестировали, статус, сколько вопросов,
сколько ответов и пропусков, сколько раз подсмотрен ответ и сколько ушло времени. Нажмите на строку,
чтобы увидеть темы и уроки теста, все вопросы с вашими ответами и эталонами, а также ещё раз скачать
полный или упрощенный результат. Кнопка «Удалить» в строке после подтверждения удаляет тест вместе
с ответами и файлами результата.

История не привязана к пользователю: это история вашей песочницы, то есть вашей базы PostgreSQL в
Docker. Она переживает перезапуск контейнеров. Целиком она удаляется только вместе с базой: при
пересборке приложения (см. ниже) или командой `docker compose down -v`.

## Пересборка приложения с нуля

Кнопка «Пересобрать приложение» внизу левой панели нужна, когда хочется начать с чистого листа или
приложение перестало запускаться.

1. Сайт спрашивает: «Приложение будет полностью удалено и заново пересобрано, все данные прошлых
   тестов будут удалены. Продолжить?». «Нет» просто закрывает окно.
2. После «Да» сайт показывает, какой скрипт запустить для вашей ОС. Сам сайт команды на компьютере
   выполнять не может: так устроена безопасность браузера, а приложение внутри Docker не видит вашу
   систему.

Скрипты лежат в папке `scripts` проекта:

| ОС | Как запустить |
|---|---|
| Windows | Дважды щёлкнуть `scripts\rebuild.cmd` или выполнить `.\scripts\rebuild.cmd` в PowerShell из папки проекта |
| macOS | Дважды щёлкнуть `scripts/rebuild.command` в Finder или выполнить `./scripts/rebuild.command` в Терминале |
| Linux | Выполнить `./scripts/rebuild.sh` в терминале из папки проекта |

Что делает скрипт:

1. Ещё раз спрашивает подтверждение (Да/Нет) во всплывающем окне. По умолчанию выбрано «Нет».
2. Удаляет контейнеры, образы (приложение и PostgreSQL) и том с базой:
   `docker compose down --volumes --rmi all --remove-orphans`.
3. Заново собирает и запускает приложение: `docker compose up -d --build`.
4. Ждёт, пока сайт ответит, и открывает http://localhost:8097 в браузере.
5. Закрывает своё окно. При ошибке окно остаётся открытым, чтобы было видно, что пошло не так.

Docker Desktop (или Docker на Linux) должен быть запущен. Банк вопросов заливается заново из миграций,
а история тестирования и все скачанные ранее результаты в базе пропадают. Файлы, уже скачанные на
компьютер, остаются.

Для проверки без удаления есть сухой прогон, который только печатает шаги:
`.\scripts\rebuild.cmd -Yes -DryRun` на Windows, `./scripts/rebuild.sh --yes --dry-run` на macOS и Linux.

## Запуск

Нужен Docker Compose. Для разработки также JDK 21+ и Maven 3.9+.

```powershell
docker compose up -d --build
```

Откройте http://localhost:8097. Flyway при старте создаёт схему и заливает банк вопросов.

Для запуска из IDE нужна доступная PostgreSQL. При необходимости переопределите `DB_URL`,
`DB_USERNAME`, `DB_PASSWORD` и `PORT` (по умолчанию 8097). Тесты: `mvn test`.

## Как пополняется банк вопросов

Вопросы каждой темы добавляются в базу своей Flyway-миграцией в
`src/main/resources/db/migration`. Соглашения по маршрутам, базе и миграциям описаны в `AGENT.md`.
